cloud_queue Server-Side Rendering (SSR) & Hydration Contrasting Client-Side Rendering against modern Angular Hydration models
Modern Angular supports full non-destructive hydration. Instead of wiping out pre-rendered server DOM nodes and rendering from scratch on boot, Angular matches the client code to existing elements, reducing layout shifts and achieving instant interactivity.
devices

1. Client-Side Rendering (CSR)

The browser receives an empty index shell <app-root></app-root> and downloads javascript bundles. The page remains completely blank until scripts are parsed and run.

dns

2. Server pre-render (SSR Paint)

A Node.js server executes Angular ahead of time, serving fully formed static HTML content immediately. Users see text/images instantly, but elements aren't interactive yet.

opacity

3. non-destructive Hydration

Client-side script runs and "hydrates" the DOM. It binds event listeners and starts CD (Change Detection) directly on the existing elements without re-drawing the page layout.
